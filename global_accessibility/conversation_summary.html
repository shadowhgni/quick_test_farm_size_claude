1. What was asked, and what was done

  1. Fork microsoft/RoadDetections and test the artefact Claude_merge_roads_v00.py on Benin and Togo. Forking or creating repositories was not possible from this session (no GitHub API; a push to shadowhgni/RoadDetections was refused with 403 because it was outside the session's authorised repositories). All work went to the branch above.
  2. Test and fix the merge script, run it in GitHub Actions, report how to deploy locally. Fixes included parsing WidthMeters as a number (it is a string in the 2025.04.28 Microsoft drop). Real-data runs happened in CI because the session could not download the data directly.
  3. Friction maps for 2020 and 2026 with speeds by road class and topography, then travel time to cities ≥50,000 and to ports, with all Nelson et al. size classes available.
  4. Organise into folders; results for nine Beninese towns (Parakou, Kandi, Malanville, Cotonou, Porto-Novo, Comè, Sakété, Natitingou, Djougou), in accessibility_update/.
  5. A stand-alone Python 3.13 script for one HPC node (up to 90 cores, no Apptainer or Singularity): installs missing packages, has start and end years in a configuration block, gives 1 km and 10 km COGs, global PNGs and a methods folder, and deletes intermediate files. It adds a corruption penalty on road speeds and a border delay in Africa only → global_accessibility/global_accessibility.py (v1).
  6. Decisions on penalties: World Bank WGI Control of Corruption, K = 0.10, also applied at the border; border delay 15 min instead of 60; only at official checkpoints (major roads crossing a land border), for walking and goods alike; ECOWAS not exempt; Europe and the rest of the world not penalised; one WorldCover 2021 map for both years.
  7. Compare with Nelson et al. (2019) using the latest figshare version (v4, the same rasters as the v3 cited by R geodata, checked by MD5), reference year 2015; validate the end year with a free routing engine (OSRM).
  8. Units and water: travel times are in minutes. Waterways and ferries are not used as links. Roads on cells that are ≥90% water are removed unless tagged as a bridge, causeway, ford or embankment.
  9. “Our 2015 is slower than Nelson”: as you asked, the 2015 OSM roads are completed with the roads of the Weiss et al. (2018) 2015 friction surface before any calculation, and the comparison is also reported where OSM 2015 was complete.
  10. Manuscript with Methods, Results, Discussion and Supplementary material in one Word file; the HPC script shared.
  11. v2: sensitivity analysis of K ∈ {0, 0.05, 0.10, 0.20} and border delay ∈ {0, 15, 30, 60} min → global_accessibility_v2.py.
  12. What are “mean diff” and “mean abs diff”; express them relative to Nelson. Added relative bias, relative mean absolute difference and median per-cell % difference; Table 3 rebuilt. This led to two bug fixes (section 5) and version 2.0.1.

2. Method in brief

ComponentChoice
GridWGS84, 30″ (~1 km), −180…180° / −60…85° (the Nelson et al. grid); light version 300″ (~10 km)
RoadsOSM Geofabrik snapshots on 1 January of each year; speed by highway class, unpaved × 0.7; fastest road per cell. Microsoft ML roads for the end year only, at 15 km/h, where there is no OSM road
2015 completionAdds a road to a cell where OSM 2015 has none, Weiss 2015 speed is ≥10 km/h, the end-year OSM has a road and the cell is not open water; speed = min(Weiss, end-year OSM). 79,233 cells added in the test domain verified
Off-roadWorldCover 2021 walking speeds × Tobler exp(−3.5 tan θ), slope from Copernicus GLO-90
CorruptionWGI score S (0–100); c = 1 − S/100; road speed × (1 − K·c), K = 0.10
BordersAfrican land borders only, at checkpoints (motorway to secondary roads): 15 min / (1 − K·c̄)
DestinationsGHSL R2023A urban clusters (SMOD 21–30) with GHS-POP, nearest epoch; World Port Index; the 12 city and 5 port layers of Nelson et al.
Cost distanceMulti-source Dijkstra, 8 neighbours, geodesic step lengths, wraps at the dateline (numba)
ParallelismWorkers sized from cgroup CPU and memory limits, per-task memory plus 0.35 GB process overhead, within 75% of memory

Comparison with Nelson et al. (2019), 2015 layers verified

d = ours − Nelson per cell. Bias = mean d, in brackets Σd / ΣNelson. Mean abs. diff. = mean |d|, in brackets Σ|d| / ΣNelson. Ratios of sums stay defined inside cities, where Nelson is about 0 min. Median cell diff. = median of 100·d/Nelson over cells with Nelson > 0, the statistic Nelson et al. used against Google Maps.

  • Completing the 2015 roads cut the population-weighted bias for cities ≥50k from +46% to −4%, and the area bias from +70% to +16%.
  • The area bias (+16%) is larger than the population-weighted bias (−4%), so our estimates are longer mainly in sparsely populated cells inference.
  • The 2026 rows compare our 2026 map with Nelson's 2015 map, so they mix real change with differences in method.
  • No 2° tile reached the 80% OSM 2015 completeness threshold (14–73%, median 39%), so the “OSM 2015 complete” subset is empty in this domain.
  • The OSM-only rows come from a second pass of the same 2.0.1 code with --no-weiss, on identical inputs.

Validation against OSRM, 2026 verified

12 sampled settlements ≥50k, 120 origin–settlement pairs 12–149 km apart; 105 kept after a ≤1 km snap filter. Median travel time 118.7 min here vs 113.5 min in OSRM; median ratio 0.98; median difference −1.6 min; mean absolute difference 14.2 min; 90.5% within ±30%; r (log) 0.94. Both use current OSM, so this tests the speed model and routing rather than the completeness of the network.

Running on the HPC

python global_accessibility_v2.py --dry-run   # grid, workers, memory, OSM downloads
python global_accessibility_v2.py             # full run; rerun the same command to resume after a crash

Options: --start --end --bbox W S E N --stages --max-workers --no-cleanup --no-ml --no-weiss --no-routing --no-sensitivity --sens-design oat|full --routing-cities N --work-dir --results-dir. The README gives rough needs for a global run: about 170 GB of OSM downloads, about 150 GB of intermediate grids, and peak RAM of about 8 GB per parallel travel-time task plus 15 GB. These are estimates, not measured on a global run.

5. Bugs found in this last round (fixed in 2.0.1)

  • Empty inputs manifest on resumed runs. A rerun without the download stage wrote an empty methods/inputs_manifest.csv and then crashed reading it. This caused the failed Actions job you reported.
  • Stale travel times after a friction rebuild. A resumed run reused finished travel-time layers even when the friction grid had been rebuilt, for example after changing K or the speeds. A layer is now reused only if it is newer than its friction grid. A new test fails on the old code and passes on the new.

After both fixes, the regional CI run finished with no traceback and 21 of 21 tests passed verified.
